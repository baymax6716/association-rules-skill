# 問卷資料：從答案到項目集合

依據 Tan et al. (2019) 6.1 節（Handling Categorical Attributes，p.451–454）與 6.2.1 節
（Discretization-Based Methods，p.454–458）。

核心觀念：**basket 不一定是購物籃，也可以是一位受訪者的特徵集合**。

| 受訪者 | 年齡層 | 居住地 | 政策 A | 政策 B |
|---|---|---|---|---|
| R001 | 18–29 | 南部 | 支持 | 反對 |

R001 的項目集合是 `{年齡層=18–29, 居住地=南部, 政策A態度=支持, 政策B態度=反對}`。
項目一定要保留「欄位=值」的形式。只留下「支持、反對」的話，分不出是支持哪一項政策。arules 的
`as(data.frame, "transactions")` 也是用這種 `variable=value` 表示法。

得到的規則例如 `{年齡層=18–29, 居住地=南部} → {政策A態度=支持}`。它描述的是樣本中的共同出現，
**不能解讀成年齡或居住地造成政策態度**。

## 第一步：確認觀測單位與資料格式

| 問題 | 交易資料 | 問卷資料 |
|---|---|---|
| 一個觀測單位是什麼？ | 一張訂單 | 一位受訪者，或一次訪問 |
| 同一單位有多列嗎？ | 每個商品一列 | 通常一人一列；長格式時每題一列 |
| ID 的用途 | 彙整訂單 | 識別受訪者與重複訪問 |
| 哪些資訊不當項目？ | 訂單編號、時間戳記 | 受訪者編號、調查權重等 |

同一位受訪者接受多次訪問（ID 重複）時，不能直接把所有答案混成一個集合。必須先決定分析單位是
「人」還是「人 × 訪問波次」。`encode` 偵測到 ID 重複時會提醒。

## 第二步：辨識每個欄位的角色與意義

不能只看資料型別。數字 1、2、3 可能是滿意程度，也可能是北、中、南。因此問卷最好附上**題目說明或
編碼表（codebook）**。

| 欄位類型 | 例子 | 處理 | `encode` 的做法 |
|---|---|---|---|
| 識別欄位 | 受訪者編號 | 保留供追蹤，不當項目 | 自動排除（`--id-col` 可指定） |
| 名目類別 | 地區、職業 | 轉成「欄位=類別」 | 預設 |
| 二元答案 | 支持 / 不支持 | 兩種答案都編成項目 | 預設（兩個值都會產生項目） |
| 次序類別 | 非常不同意 ～ 非常同意 | 可保留各級；合併要交代理由 | `--merge` 並印出合併前後對照 |
| 連續數值 | 年齡、收入 | 先決定分組與切點 | `--bins`；沒指定時自動排除並列出分位數 |
| 複選題 | 關注教育、交通、環境 | 每個選項轉成一個項目 | `--multi 欄位 --multi-sep ;` |
| 自由文字 | 意見說明 | 第一版不自動納入，需要另行編碼 | 自動排除 |
| 設計資訊 | 權重、分層、群集 | 保留為分析資訊，不當一般項目 | 權重自動排除並提醒（`--weight-col`） |

注意：五點量表轉成項目後，標準關聯規則把每個答案當成獨立類別，**不會利用「非常同意比同意更高」
的順序資訊**。

### codebook 格式

```csv
column,code,label,missing
政策A態度,1,支持,
政策A態度,2,反對,
政策A態度,98,不知道,dont_know
政策A態度,99,拒答,refused
```

`missing` 欄可以填 `refused`（拒答）、`dont_know`（不知道）、`na`（不適用），一般答案留空。

## 第三步：先處理缺失、跳題與分組，再編碼

| 情況 | 決策 | `encode` 參數 |
|---|---|---|
| 99 代表拒答、98 代表不知道 | 依 codebook 轉換，不能當成一般數值 | `--codebook` |
| 「不知道」是正式選項 | 可以保留成獨立類別，並說明它的意義 | `--missing-codes keep` |
| 空白代表漏答 | 不可以自動當成「反對」或「未選」 | 預設：空白不產生項目 |
| 空白是因為跳題、不適用 | 先界定適用的受訪者，再決定分析範圍 | `--where 就業狀態=就業` |
| 連續變數需要分組 | 優先使用有實際意義的切點；也可以比較等寬、等頻 | `--bins 年齡=18,30,45,65`、`=quantile:4`、`=width:10` |
| 某些類別人數很少 | 報告人數；只有語意合理時才合併 | 摘要會提醒；`--merge` |
| 要保留資料做驗證 | 資料導向的切點只在探勘集決定，再固定套用 | `split --format survey`，然後 `--cuts-out` / `--cuts-in` |

**缺失處理不能只交給套件的預設值**。有些轉換會略過缺失項目但保留該受訪者，這不等於處理了缺失造成
的偏誤。例如只有就業者回答工作滿意度時，應先說明分析對象是就業者，不能把沒被問到的人當成
「不滿意」。`encode` 會自動偵測「空白集中在某個答案」的跳題型態並提醒。

**離散化的取捨（6.2.1）**：區間太寬，規則的 confidence 會被稀釋而消失；區間太窄，每個區間的
support 不夠而消失。所以要列出各組人數讓使用者判斷，必要時比較兩種切法。

## 第四步：建立項目集合，檢查會不會產生無意義規則

要區分以下幾種情況：
- 購物資料：沒出現咖啡，通常只是沒有「咖啡」這個項目。
- 問卷資料：回答「不支持」本身就是有意義的項目，`政策A態度=不支持`。
- 沒有回答：不能等同於不支持。

若把問卷答案直接存成布林值，有些套件只保留 TRUE 對應的項目，所以兩種答案都要研究時，要明確編成類別。

| 檢查項目 | 例子 | 自動處理 |
|---|---|---|
| 單選題出現互斥答案？ | 同一人同時有「政策A=支持」與「政策A=反對」 | 每題每人最多一個值；同一題的不同值不會出現在同一個 itemset（6.1） |
| 同時納入原始變數和衍生變數？ | 「年齡=25」與「年齡層=18–29」 | 偵測欄位間的函數關係並提醒 |
| 有沒有定義上必然成立的規則？ | 「縣市=台南」→「區域=南部」 | `mine` 自動標成「定義性」並排除 |
| 混入了唯一識別碼？ | 「受訪者ID=R001」 | 每列都不同的欄位會自動排除 |
| 類別合併與分組有紀錄嗎？ | 哪些收入區間被合併、理由是什麼 | 摘要列出合併前後對照，`encoding.json` 留存設定 |
| 高頻值 | 85% 的人都「使用網路=有」 | 提醒加 `--hconf` 或排除該值（6.1、5.8） |

「台南 → 南部」即使 confidence 是 100%，也只是地理定義，不是有價值的新發現。

## 第五步：輸出前處理摘要，再進入參數設定

`encode` 的摘要固定包含下表內容，這也是確認 ① 要給使用者看的東西：

| 項目 | 內容 |
|---|---|
| 分析單位 | 一人 / 一次訪問 / 一張訂單 |
| 分析對象 | 全部樣本，或符合哪些條件的子樣本 |
| 納入欄位 | 哪些題目或商品資訊 |
| 排除欄位 | ID、自由文字、權重、未分組的連續變數等，附原因 |
| 缺失與跳題處理 | 排除、保留成類別，或限定適用人群 |
| 連續變數切點 | 切點數值、選擇理由、各組人數 |
| 轉換結果 | 觀測數、項目數、項目頻率 |
| 分母 | 支持度實際以哪些觀測單位計算 |
| 規則限制 | 指定後件、禁止的結構性規則等（在確認 ② 決定） |

使用者應該能從摘要看懂「接下來分析的是什麼」，而不只是看到「轉換成功」。

## 調查權重

一般按人數計算的支持度是：support(A) = 具有項目集 A 的受訪者數 / N。它描述的是**分析樣本**。
資料有調查權重，而使用者又想推論到母體時，不能把未加權的比例直接說成全民比例。

本 skill 第一版的做法：只做未加權的樣本關聯探索；偵測到權重欄位時提醒「結果尚未做母體加權估計」。
這比把權重複製成多筆受訪者，或忽略權重直接做母體推論更清楚。之後即使加入加權比例，標準誤與顯著性
也還需要考慮抽樣設計（分層、群集）。

## 完整指令範例

```bash
# 全部資料先看一次設定摘要
python scripts/run_arules.py encode data/sample_survey.csv --codebook data/sample_codebook.csv \
    --bins 年齡=18,30,45,65 --multi 關注議題 --exclude 縣市
# 驗證安排（切點固定，可在編碼後切分）
python scripts/run_arules.py split arules_output/items.csv --method random --test-frac 0.3
# 只用人口特徵解釋政策態度
python scripts/run_arules.py mine arules_output/train.csv --min-count 20 --max-lhs 2 --max-rhs 1 \
    --rhs 政策A態度 政策B態度 --hconf 0.1 --min-lift 1.2
python scripts/run_arules.py validate arules_output/test.csv --rules arules_output/rules.csv --min-test-count 5

# 資料導向切點（等頻）：先切分再編碼
python scripts/run_arules.py split data/sample_survey.csv --format survey --method random --out-dir out
python scripts/run_arules.py encode out/survey_train.csv --codebook data/sample_codebook.csv \
    --bins 年齡=quantile:4 --cuts-out out/cuts.json --out-dir out --output train.csv
python scripts/run_arules.py encode out/survey_test.csv --codebook data/sample_codebook.csv \
    --cuts-in out/cuts.json --out-dir out --output test.csv
```
