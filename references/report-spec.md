# 報告規格

`run` 產生的 `report_draft.md` 已經有完整的章節、表格與數字，你只負責把 `【待填：…】` 換成文字。
表格、數字、程式碼區塊都不要刪改。

## 章節

| 章 | 程式產生的內容 | 你要填的 |
|:--|:--|:--|
| 1. 分析目的與資料 | 分析目標、一筆觀測、support 的分母 N、因果提醒 | 背景（使用者沒提供就寫「未提供」）；用使用者的話寫出分析問題 |
| 2. 前處理 | 前處理紀錄（處理、原因、影響筆數）、分析前後筆數、編碼對照（問卷）、前處理程式碼 | 一到三句：前處理對資料的影響，例如排除比例與可能的偏誤 |
| 3. 分析設定 | 本次設定（支持度與對應筆數）、設定紀錄、篩選過程、規則產生程式碼 | 設定理由（若 config 沒寫） |
| 4. 結果與解讀 | 前 20 條規則表 | 主要規則的白話解讀 |
| 5. 規則穩定性 | 有做保留資料驗證時的檢定結果；沒做時的說明 | 有做時：哪些重現、哪些沒有 |
| 6. 結論與建議 | — | 回答分析問題、可以考慮的行動 |
| 7. 限制 | 固定的限制 | 本次資料特有的限制 |
| 附錄 | 指標定義、重現方式、config、完整程式碼（由 `finalize` 附上） | 不用填 |

## 解讀寫法

數字只能取自草稿表格或 `results.json`，位數照抄，不重新計算。每條規則至少說清楚四件事：

1. **分母**：N 是什麼（幾筆交易、幾位完整回答的受訪者）。
2. **共同筆數**：前件與後件一起出現幾筆。
3. **confidence 與後件比例的對照**：「買 whole milk 的交易中有 10.78% 也買了 butter，所有交易中只有 5.54%」。
   不能只寫 confidence。
4. **lift**：「約為 1.95 倍」。lift > 1 只表示比獨立時更常一起出現，不代表顯著。

**範例**：

> 在 10 位完整回答的受訪者中，不網購的 4 人裡有 3 人幾乎不運動（confidence 0.75），而全部 10 人中只有 3 人幾乎不運動（0.3），lift = 2.5。

- 問卷結果寫成「在這份樣本中……」，註明未加權、排除了幾位缺失者。
- 多條規則其實來自同一小群觀測時（例如三個回答兩兩成對出現），合併說明，不當成好幾個獨立的發現。
- 備註「定義上必然成立」的規則，要說明它不是新發現。
- 有做保留資料驗證時，以「重現 = 是」的規則為主；沒重現的只能當線索。
- 沒做保留資料驗證時，結論註明是描述性、探索性的。
- 沒有規則時，如實寫「在本次設定下沒有規則」，並引用設定紀錄說明試過哪些設定。

## 不能寫的話

- 因果用語：「導致」「造成」「因為買了 A 所以買 B」。
- 「顯著」：除非做了保留資料驗證並通過檢定。
- 母體比例：「75% 的民眾……」（問卷未加權、只是樣本描述）。
- 程式沒有算的數字，例如營收、利潤、轉換率。
- 把缺失、不知道、拒答解讀成「否」。
- 「示範設定是標準門檻」或類似說法。
- 沒有根據的行動保證，例如「這樣做一定能提升銷售」。行動建議寫成「可以考慮」，必要時建議用實驗確認。
