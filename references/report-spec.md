# 報告規格

`run` 產生的 `report_draft.md` 已經有完整的章節、表格與數字，你只負責把 `【待填：…】` 換成文字。
表格、數字、程式碼區塊都不要刪改。

## 章節

| 章 | 程式產生的內容 | 你要填的 |
|:--|:--|:--|
| 1. 分析目的與資料 | 分析問題、觀測單位、資料檔 | 背景（使用者沒提供就寫「未提供」） |
| 2. 前處理 | 前處理紀錄表（處理、原因、影響筆數）、答案分布、前處理程式碼 | 一到三句：前處理對資料的影響 |
| 3. 分析設定 | 規則形式、門檻與計算方式、驗證安排、篩選過程表、探勘程式碼 | 不用填 |
| 4. 結果 | 前 20 筆結果表 | 回答分析問題的白話解讀 |
| 5. 可靠性檢查 | 檢定方法、重現數 | 哪些重現、哪些沒有、代表什麼 |
| 6. 結論與建議 | — | 回答分析問題、可以採取的行動 |
| 7. 限制 | 固定的限制 | 本次資料特有的限制 |
| 附錄 A–C | 指標定義、重現方式、config、完整程式碼（由 `finalize` 附上） | 不用填 |

## 解讀寫法

- 數字只能取自草稿表格或 `results.json`，位數照抄，不重新計算。
- 每個結論都要回到使用者選的分析問題，用諮詢者看得懂的話說：
  - 套餐：「在 6,885 張訂單中，有 529 張同時買了 A 和 B（7.7%）；每一項和其他項一起買的機會都比平常高（最低 lift 1.50）」。
  - 推薦：「買 XX 的訂單中有 10.3% 也買了 butter，整體只有 5.5%，約為 1.9 倍」。這裡要同時寫 confidence 和後件基準比例。
  - 相近位置：說明 lift 高、cosine／Kulczynski 也不太低的組合比較值得調整；lift 高但 Kulczynski 很低，通常是其中一項很稀有。
  - 問卷：寫成「在 X 的受訪者中，有 p% 是 Y，整體只有 q%」。不能寫成「X 會導致 Y」。
- `given` 問題中 lift ≤ 1 的結果，要說明「這個答案本來就常見，不是這個特徵特有」。
- 解讀以「重現 = 是」的結果為主。沒有重現的結果只能當作線索，不能當成主要結論。
- 沒有驗證的分析（觀測單位 < 300，或使用者不要驗證），全部結論都要註明「探索性」。

## 不能寫的話

- 因果用語：「導致」「造成」「影響」「因為買了 A 所以買 B」。
- 程式沒有算的數字，例如營收、利潤、轉換率。
- 把缺失或未作答解讀成「否」。
- 對 confidence 的單獨解讀：沒有和後件基準比例比較，就不能說「關聯很強」。
- 沒有根據的行動保證，例如「這樣做一定能提升銷售」。行動建議要寫成「可以考慮」，並建議用實驗確認。
